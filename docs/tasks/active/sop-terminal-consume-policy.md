## 目标

- 第三方任务已到达但内容缺失时，不再长期占用：消费任务 `70`，不消费消息内容，回传失败策略数据并告警。
- 聚合平台明确拒绝发送时，不再长期占用：消费任务 `70`，不消费消息内容，回传失败策略数据并告警。
- 主动发送接口一旦发起，若结果因连接/读取超时或连接中断无法确认，按业务约定不再重发，联合消费任务 `30` 与本次唯一 `msgId=30`，保留“调用已发起、结果未确认”审计。

- 不修改第三方 API 或数据库 schema。
- 不补发、手工消费或修改现有生产任务；上线后由正常恢复链处理。
- 不将聚合平台明确拒绝伪装为发送成功。

## Change contract

- type: SOP terminal consumption policy
- scope: 第三方 SOP 确定性执行/恢复、消费和策略回传、失败告警、合同及最小临时验证
- risk: 超时可能发生在 TCP 建连前，按业务约定消费 `30` 会产生“实际未发送但任务成功”的假阳性；错误联合消费可能越过前序任务
- validation: 内容缺失、明确聚合拒绝、连接/读取超时、普通本地异常、消费失败恢复、唯一 msgId 与严格顺序矩阵
- rollback: `ai-paths-unified-20260909-v3-supervisor-3192f19a`

## 不可破坏边界

- 任务状态接口不支持任务 `40`；失败终态只能用任务 `70 + remark` 表达，并以策略数据/告警保留失败性质。
- 未调用主动发送时不得消费任何 `msgId`。
- 主动发送尝试的唯一 `msgId` 必须在调用前持久化；任务 `30` 必须与该 `msgId=30` 同一次消费。
- 聚合平台明确拒绝与结果未知必须分开处理。
- 后续任务只有在前序任务完成 `30/70` 终态后才可继续。
