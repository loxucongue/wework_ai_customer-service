## 任务使命

独立判断素材治理候选是否真正满足产品目标、数据库安全和运行边界，不能把原执行窗口的测试摘要直接当作验收结论。验收窗口应自主审阅完整差异、重跑证据并补齐原候选明确缺失的生产同类数据库与前端验证。

验收目标有四个：

1. 同一物理素材在 AI 生成侧跨来源、换址、常见转码、进程重启、并发和重放后不再重复，同时不误杀正常新素材或跨接触档案串账。
2. 内容素材、跟进序列和卡点话术不能隐式获得收款、门店、预约确认或写动作；现有合法权威动作仍正常。
3. `response_committed` 的持久占用与稳定响应同事务，既不会因尾部失败留下幽灵占用，也不会被日志、接口或文档误称为已发送/已送达。
4. 迁移、回填、回滚和运行性能达到可安全集成的标准，并且没有引入第二套业务规则、额外模型调用或热路径下载。

## 已确认边界

- 未知身份附件失败关闭，但文字沟通和销售推进继续；不得虚称已经发图。身份补齐后允许后续恢复交付。
- 没有权威失败事件时不自动解除 `response_committed` 占用；当前接受平台实际失败后可能不自动补图的保守取舍。
- `response_committed` 只证明 AI 已提交稳定响应，绝不等于平台发送成功或客户送达。
- 实际发送闭环需要未来建立 `response_id/client_message_id` 与 `dispatch_id` 的权威映射，属于独立第三方接口任务，本验收不得扩大公共协议。
- 感知指纹是保守近似；视频转码依赖可靠文件 ID 或人工登记；错误别名已占用后只能通过独立审计迁移纠正。
- 本任务不改变 Reply 的销售语义、软承接口径、V3 唯一决策权或客户接触档案边界。

## 自主权限

- 可以读取候选完整代码、历史、架构和合同，建立独立 change contract 和风险清单。
- 可以在隔离环境使用合成/脱敏数据运行测试、启动一次性 MySQL 实例、执行升级/降级/重入/并发验证及完整前端构建。
- 可以在验收分支选择性带入候选，并修复不改变产品语义、公共接口或数据边界的明确工程缺陷；修订必须有针对性回归证据。
- 若发现产品语义冲突、不可逆数据风险、必须改变公共接口或无法证明数据库安全，停止集成建议并回母窗口。
- 不读取真实客户原文，不调用真实模型，不发送客户消息，不写生产或第三方数据，不推送 main，不部署。

## 必须独立核验的证据

### 代码与架构

- 逐项追踪素材身份从目录/同步、候选 Join、Reply 选择、最终响应到持久占用的完整数据流。
- 审查 canonical key、alias/provenance/role 的唯一性、版本、冲突处理和人工 override，确认不同角色不会错误更新业务阶段。
- 审查内容能力过滤是否覆盖所有入口，不能通过结构补全、修复或 legacy 字段重新带入交易动作。
- 审查异常路径：目录/数据库不可用、未知字节、指纹失败、事务回滚、重试、并发、旧 schema 和历史缺失。
- 核对日志、管理页、合同和字段名不把响应提交写成已发送/送达，也不泄露签名 URL 或素材字节。

### 数据库与迁移

- 使用与生产同类的隔离 MySQL 实例验证 Alembic 正向迁移、重复执行防护、必要降级/回滚和旧数据兼容；不得只依赖 SQLite。
- 在真实 MySQL 事务与唯一约束下验证并发抢占、同响应重放、失败回滚和进程重启。
- 用合成目录验证 dry-run、apply、重复 apply、中断恢复、候选过期拒绝和受保护 rollback。
- 检查表/索引规模、查询路径、锁范围及潜在死锁，给出正常热路径的明确性能上界或测量结果。
- 历史缺失无法还原的范围必须可审计；不得以猜测回填成已发送或已确认身份。

### 回归与构建

- 重跑候选声称的三组核心证据和全量确定性后端测试。
- 对误合并进行独立反例测试，包括近似但不同图、图片/视频隔离、不同 canonical 版本和跨企微身份。
- 对动作隔离验证活动、效果、话术等所有内容角色，以及合法收款/预约/门店能力未被破坏。
- 运行所有变更代码的静态检查和差异检查。
- 安装/复用项目锁定依赖并完成正式前端构建；单独 TSX 语法转译不算完整构建验收。

## 结论门槛

只有以下条件同时满足，才可建议母窗口进入集成：

- 没有未解决的 P0/P1 正确性、数据一致性、安全或身份隔离问题。
- MySQL 迁移和真实事务并发验证通过，回填方案可逆且不会猜测历史事实。
- 全量确定性测试、相关专项和完整前端构建通过。
- 运行时边界与长期合同一致，无额外模型调用、热路径下载或公共协议扩张。
- 风险说明准确区分 AI 生成侧去重与第三方实际发送/送达。

未达到门槛时应给出最小修订方案和证据缺口；达到门槛时形成干净的验收候选并回报母窗口，仍不得自行推送 main 或部署。

## 完成回报

只向母窗口提供 `结论 / 改动 / 证据 / 风险 / 下一步`，其中必须明确：

- 候选是否可集成，以及是否发生修订。
- 关键代码审查结论和 P0/P1 发现。
- MySQL、迁移、并发、回填、全量后端、完整前端构建的实际证据。
- 尚未覆盖的 L2–L4 与第三方依赖。
- 建议合入、退回修订或拆分后续任务，不得以“测试通过”代替产品验收。
