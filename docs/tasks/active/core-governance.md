## 目标

把当前“清晰的运行外壳 + 巨型业务内核”收口为单一职责架构：

- Reply、Control、Worker 只获得各自所需依赖。
- Semantic Router 只提供语义证据；Reply 是唯一客户可见销售决策来源。
- Outreach 与第三方 SOP 使用可读、可测试的明确阶段。
- 长期测试只验证公开业务合同，不以私有函数维持旧实现。

## 非目标

- 不修改 V3、回调和管理端公开接口。
- 不修改数据库 schema、Prompt 业务含义和功能开关。
- 不部署生产，不调用真实模型、真实发送或生产写接口。
- 不引入抽象基类、注册器、事件总线、动态代理或兼容双轨。

## 不可破坏合同

- V1/V2 不恢复；三个角色来自同一个 `main` 提交。
- 身份边界为 `corp_id + wechat + external_userid/customer_id`。
- 人工接管、明确退订、订单、支付、门店和素材 URL 是硬边界。
- 第三方 SOP 保留 `pending` 触发节点与 `store-visit-pending` 内容节点配对。
- 消费、策略数据回传和消息送达分别审计；失败不得伪造完成。
- 测试不得调用真实模型、真实发送或生产写接口。
