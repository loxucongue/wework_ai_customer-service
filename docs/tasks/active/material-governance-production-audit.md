## 背景

统一素材身份、跨来源去重、内容/动作隔离和 `response_committed` 占用已经合入 main。最新生产快照显示，该代码和加法迁移随后随第三方 SOP 修复一起发布，但生产目录/历史是否完成身份同步没有闭环证据；现有同步 CLI 在独立验收时仅明确支持本地 SQLite。

未知身份附件采用失败关闭：无法确认物理身份时图片/视频不发送，文字链路继续。因此当前最大风险不再是代码能否迁移，而是生产素材目录中有多少资产仍无法确认身份、是否已经造成素材交付下降，以及如何在不猜测历史事实的前提下安全完成 MySQL 目录同步和必要回填。

执行窗口已触发停止条件并确认 P1：生产 `material_identities=0`、`material_claims=0`；Follow Knowledge 522 条话术包含 299 个仅 URL 的媒体附件（235 图片、64 视频），可靠 `file_id=0`；最近两个 24 小时窗口抽查 141 个 V3 run，图片/视频结构附件和身份治理成功记录均为 0。三个后端服务健康，说明是素材身份前置条件缺失造成的系统性媒体关闭，不是整体服务宕机。

母窗口与产品负责人已确认事故取舍：不接受长期媒体不可用，不整版回滚已上线的素材治理与 SOP 修复；优先完成可靠身份目录并受控回填。历史状态只恢复有证据的部分，禁止猜测；接受被历史截断且无法证明的旧发送记录可能留下少量重复风险，以换取正常媒体交付恢复。

## 任务使命

在同一个现有子窗口中连续完成安全 MySQL 同步工具、身份计划生成、隔离演练、L2/L3、候选自审、main 集成、生产前备份与 dry-run，并在以下自动门槛全部通过时执行生产身份回填和只读验证。不要在正常阶段返回母窗口领取下一步；任务范围内发现的工程缺陷应自主修复并复验。

本任务获得一次性条件授权：可以合入经过验证的工具并从 clean main 执行计划限定的生产素材身份/别名及可证明历史占用回填。不得执行 schema DDL、服务代码部署、服务重启、业务配置修改、客户发送或第三方写入。

## 产品目标

1. 明确当前生产是否已经受到素材身份未知的影响，不能只看代码或迁移成功。
2. 建立生产素材目录的真实身份覆盖率、重复组、未知组和业务可用性清单，但不把素材 URL、字节或客户信息写入 Git。
3. 让生产 MySQL 可以通过默认 dry-run、显式 apply、可重入、可中断、可审计和受保护回滚的方式同步 canonical identity；本任务只在隔离环境验证该能力。
4. 证明回填计划不会猜测历史已发送事实、不会跨 `corp_id + wechat + external_userid` 串账，也不会把不同图片、图片与视频错误合并。
5. 证明素材身份治理没有破坏正常文字回复、合法素材交付、合法收款/预约/门店能力和允许的销售性软承接。
6. 在全部门槛通过后安全恢复生产素材身份目录，验证正常素材重新具备可交付资格，并留下可重复使用的发布前覆盖门禁、停止条件和回滚方案。

## 已确认能力边界

- Reply 仍是唯一销售语义决策者；目录、跟进序列、素材和代码不能授予收款、门店、预约完成或写动作。
- 未知身份只关闭媒体附件，不关闭文字沟通和正常销售推进，也不得虚称“已经发图”。
- `response_committed` 只表示 AI 已提交稳定响应并占用素材，不等于平台发送成功或客户送达。
- 没有权威失败事件时不自动释放占用；平台发送失败可能不自动补图是当前已接受限制。
- 感知指纹是保守近似，不是绝对物理同一性证明；视频转码依赖可靠文件 ID 或人工登记。
- 错误别名已经占用后不得自动释放，只能通过独立审计迁移纠正。
- 实际发送闭环及 `response_id/client_message_id ↔ dispatch_id` 映射属于第三方接口任务，不在本任务扩张公共协议。

## 技术要求

### 1. 现场影响审计

- 重新核验当前生产完整 SHA、dirty 状态、三个后端角色、前端、schema head、服务重启和错误状态。
- 确认素材治理运行代码是否已经生效，不能仅以迁移表存在推断。
- 统计所有当前可进入 V3 的素材：来源、媒体类型、业务角色、可靠 file ID、字节哈希、感知指纹、canonical/alias 状态、未知原因和跨来源重复组。
- 对比发布前后可获得的等长时间窗，聚合观察素材候选、成功身份、未知关闭、selected、`response_committed` 和结构附件比例。样本不足必须标明，不做强因果结论。
- 核查审计与管理日志没有把响应提交写成发送/送达，也没有泄露签名 URL。

### 2. 安全 MySQL 同步与回填准备

如现有工具无法安全面向生产 MySQL，补齐单一正式路径，至少满足：

- 默认只 dry-run；生产 apply 必须显式参数、明确数据库目标、计划文件和二次确认，测试环境不得误连生产。
- 计划绑定目录版本/checksum、schema head、生成时间和统计摘要；apply 前发现目录或数据库漂移必须拒绝。
- 可靠 file ID 优先；可取字节时使用精确哈希和版本化保守感知指纹；URL 不能单独冒充物理身份。
- 未知项保持 pending/disabled，不写成 verified，不猜测历史发送。
- apply 幂等、可中断和可恢复；有界批次、锁等待、超时、死锁重试和进度审计，不长时间锁住客户回复热路径。
- rollback 只能撤销该计划新增且尚未被业务占用的记录；已经 `response_committed` 的身份和别名不得自动释放。
- dry-run、apply 和 rollback 不输出凭证、签名 URL 或素材字节。

### 3. 隔离验证

- 用全新 MySQL 8/InnoDB/REPEATABLE-READ 验证迁移、重复迁移、旧 schema 兼容、目录同步、重复 apply、中断恢复、漂移拒绝、并发、回滚和进程重启。
- 使用生产规模或更大规模的合成目录与账本测量查询、计划和 apply 性能；已知素材请求热路径不得联网下载，身份 Join P95 目标不高于 100ms 且没有明显锁等待放大。
- 独立反例覆盖：同图跨来源、换域/签名、常见压缩缩放、相似但不同图、图片/视频隔离、不同接触档案、未知身份恢复和错误别名保护。
- 全量 L1、MySQL 专项、所有变更代码静态检查和必要前端正式构建通过。

### 4. L2/L3 行为矩阵

使用虚构客户和隔离运行环境，至少覆盖：

- 相关且 verified 的效果素材正常随短文字交付。
- 同一物理图跨来源、本轮重复和跨轮重复均只产生一次媒体交付。
- 未知身份不发附件，但文字回答非空、自然推进且不声称已发图。
- 身份后续补齐后，尚未占用且仍相关的素材可恢复候选。
- 活动、效果、跟进和卡点话术不能带出付款卡、预约完成、门店确认或写动作。
- 权威事实齐全的合法收款、预约和门店场景保持正常。
- 软拒绝和“给您留着/安排上”等软承接不被错误拦截。
- 跨企微、跨企业和跨外部联系人分别隔离。

最低门槛：结构解析 100%，硬安全 100%，未知身份附件误发 0，重复媒体结构 0，内容越权动作 0，未知身份文字链路非空 100%；合法动作如有任何回退必须判 No-Go 并定位原因。模型输出只保存在 ignored artifacts，AI 评分不冒充业务金标。

## 自动执行门槛

以下条件是本次生产回填的预授权门槛。全部满足时，执行窗口无需再次返回母窗口，可以按冻结计划执行；任一条件不满足则为 `No-Go`，禁止生产 apply：

- 生产完整 SHA、dirty 状态、schema head、服务和目录 checksum 与冻结计划一致；任何漂移都停止。
- 同步工具已经进入 clean main，最终提交只包含登记范围内的工具、测试、合同和任务文档，没有未审草稿或真实数据。
- 所有仍启用、可发送的目录素材都被明确分类为 verified 或显式 pending/disabled，不存在悄悄以 URL 当身份的未知项。
- 每个当前业务实际使用的关键素材角色/场景至少保留一个 verified 可用素材；任何场景因治理变为空都必须 No-Go，不能自行接受业务降级。
- 历史记录可证明的才回填；无法恢复的历史范围已量化，且不会被猜测成已发送。
- MySQL 同步计划可冻结、重入、恢复、漂移拒绝和受保护回滚，性能与锁范围达标。
- L1、MySQL、L2/L3 和必要前端构建达到上述门槛，没有未关闭 P0/P1。
- 已生成生产目标表的可验证备份/恢复点，且回滚流程经过隔离演练；备份不得进入 Git。
- 最终 dry-run 的新增、合并、pending、disabled、历史占用和冲突计数与冻结计划一致；任何未解释冲突、下载失败或歧义碰撞都停止。

生产 apply 必须使用冻结计划、小批次和有界事务。出现死锁、超时、行数/checksum 偏差、服务 5xx、进程重启或计划外表变化时立即停止后续批次；只有工具证明可安全撤销且目标记录尚未被 `response_committed` 占用时才执行受保护 rollback，不得为了恢复而删除真实新占用。

apply 完成后只读核验 identity/alias/claim 计数、目录覆盖、关键场景可用性、数据库锁等待、服务健康和审计口径；不得主动构造客户消息。可以观察自然流量，但不得把平台受理或 `response_committed` 写成实际发送/送达。

## 非目标

- 不治理每一张素材的业务内容是否正确、过期或适配项目；只输出需要业务确认的清单摘要。
- 不解决第三方实际发送/送达与失败补图闭环。
- 不恢复客户可见自动补答，不恢复策略 outbox 外发。
- 不执行生产 schema 迁移、服务发布、重启、配置切换或真实客户链路测试；本次唯一允许的生产写入是冻结计划限定的素材身份/别名及可证明历史占用回填。
