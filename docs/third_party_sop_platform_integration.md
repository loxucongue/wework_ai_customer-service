# 第三方 SOP 平台联调字段契约

## 结论

AI 系统只能在任务到期后，通过第三方平台的 `pending` 接口拉取状态 `10` 的任务。任务进入执行槽后调用 `consume(status=20)` 原子认领；确认发送或确认不发送后调用 `consume(status=30)` 完成。

生产默认每 `10` 秒轮询一次。AI 系统不提前消费未到期任务，不延期任务，也不创建下一次任务。

当前测试队列中的 19 条任务全部来自第三方平台，不是 AI 系统生成。Shadow 审计结果中的 19 条 `shadow_no_send` 不是 19 次模型拒绝：

| 类型 | 数量 | 是否调用模型 | 说明 |
| --- | ---: | --- | --- |
| 身份字段不完整 | 13 | 否 | 无法可靠读取聊天和主动发送 |
| 消息结构非法 | 1 | 否 | 任务 11 含空文本 |
| 超过 6 小时 | 5 | 否 | 到期过久，按过期任务保护 |

这些任务没有调用 `consume(20)`，没有发送客户消息，也没有调用 `consume(30)`，因此仍是第三方平台状态 `10`。

## 必填字段

| 平台字段 | AI 系统用途 | 缺失或错误的后果 | 联调期望 |
| --- | --- | --- | --- |
| `task_id` | 本地审计主键、平台认领/完成回写、主动发送幂等键 | 无法防重、无法回写 | 全局稳定且永不复用；任务状态变化时值不变 |
| `scheduledAt` | 判断任务是否到期、延迟和过期保护、日志排序 | 无法判断时效，可能误发旧任务 | Unix 秒、Unix 毫秒或带时区 ISO 时间；建议统一 Unix 秒 |
| `corp_id` | 选择企业主体，隔离聊天、订单、客户状态和发送身份 | 可能跨企业查错数据，必须不发送 | 必须是真实企微主体 ID，例如 `ww...`，不得为空 |
| `customerId` | 查询平台客户、订单、支付和预约事实 | 无法取得业务客户状态 | 必须是稳定的业务客户 ID，不能用示例 ID |
| `customer_wechat_id` | 查询指定客户会话并作为主动发送接收人 | 查不到聊天或发错客户，必须不发送 | 必须是平台聊天/发送接口真实可用的客户外部 ID；不得传掩码手机号、`1`、示例微信号或昵称 |
| `user_wechat_id` | 标识实际接待员工/企微成员，供聊天接口和路由使用 | 查不到正确客服会话 | 必须与聊天接口参数语义一致，不能留空 |
| `user_wechat` | 标识咨询号/接待账号，也是销售接触档案隔离边界 | 不同客服号可能串历史、串 SOP 或发送失败 | 必须是聊天和主动发送接口认可的真实账号，例如 `DY258`；不得依赖 AI 猜测 |
| `useAiCopy` | 决定只审核原文，还是允许受限改写文字 | 可能错误改写固定内容 | 必须是明确布尔值，不使用模糊字符串 |
| `message_content` | 本轮真正准备发送的可执行消息 | 无内容、空文本或非法 URL 时无法发送 | 必须是数组；支持 `text/image/video/link`；每个元素内容非空、URL 可访问 |

## 场景字段

`scene` 是第三方平台提供的任务背景，不是第二套可执行消息。建议至少提供：

| 场景字段 | 作用 | 要求 |
| --- | --- | --- |
| `sceneId` | 稳定标识场景，便于日志与效果追踪 | 同一场景稳定不变 |
| `scene.sceneName` | 人类可读的场景名称 | 与任务目标一致 |
| `scene.sceneDesc` | 说明为什么触达、期望解决什么问题 | 不得与 `message_content` 的客户阶段、项目或动作冲突 |
| `scene.knowledgeText` | `useAiCopy=true` 时允许使用的业务知识 | 只放当前有效事实，注明数字、适用范围和限制 |
| `scene.engine.generateNote` | 空 `message_content` 时的受控生成要求 | 明确目标、允许事实和禁区，不能只写抽象标签 |
| `ruleId/ruleName` | 追踪第三方策略和规则版本 | 只作审计，不替代场景内容 |
| `triggerEvent` | 说明任务由哪个事件产生 | 使用稳定枚举 |

当 `useAiCopy=false` 时，`message_content` 必须至少包含一条合法消息，AI 只能判断发或不发，不能改写。

当 `useAiCopy=true` 且 `message_content` 为空时，必须至少提供 `sceneDesc`、`knowledgeText` 或 `engine.generateNote` 中的一项可信内容。否则 AI 系统只能判定不发送。

如果 `scene` 与 `message_content` 明显冲突，例如场景写“术后回访”，实际消息却是陌生客户首次邀约或门店地址，AI 系统会判定 `no_send`，不会自行猜测哪一边正确。

## 当前测试数据问题

截至 2026-08-04，测试队列的身份缺失分组如下：

| 任务 ID | 缺失字段 | 备注 |
| --- | --- | --- |
| `2–10` | `corp_id`、`user_wechat_id`、`user_wechat` | `wecom_account` 也为空，无法补齐 |
| `13–16` | `user_wechat` | `wecom_account` 也为空，不能作为替代来源 |

还存在非空但不可用于生产的值：

- 任务 `11–12` 的 `customer_wechat_id` 是掩码手机号 `156****5906`。
- 任务 `13–16` 的 `customer_wechat_id` 是占位值 `1`。
- 任务 `11` 的 `message_content` 第一条是空文本；即使第二条图片合法，整组消息也不能原样执行。

`wecom_account` 在部分任务中与 `user_wechat` 相同，但它不是当前接口契约中的唯一权威字段。AI 系统不会在字段缺失时自行把它映射成 `corp_id`、`user_wechat_id` 或 `user_wechat`。如果第三方希望它作为正式替代字段，需要先明确其唯一语义并更新接口文档和测试。

## 联调验收

第三方平台应提供以下测试任务：

1. 一条字段完整、`useAiCopy=false` 的文本任务。
2. 一条字段完整、带图片或视频的固定内容任务。
3. 一条字段完整、`useAiCopy=true` 且含可改写文字的任务。
4. 一条 `useAiCopy=true`、`message_content=[]`、但场景知识完整的任务。
5. 一条客户已付但内容为到店提醒的任务，用于验证不会误判为催付。
6. 一条场景与消息故意冲突的任务，用于验证安全不发送。

每条任务需满足：

- 使用真实隔离测试账号，所有身份字段能被聊天查询接口和主动发送接口同时识别。
- `pending` 返回后的任务内容和身份不可变。
- 两个消费者同时调用 `consume(status=20)` 时只能一个认领成功。
- 重复调用 `consume(status=30)` 具备幂等语义。
- `message_content` 的图片、视频和链接在 AI 服务器网络环境可访问。
- 测试结束后清理或终止旧任务，避免它们长期占据状态 `10`。

## 当前接口限制

- `pending` 只返回已到期任务，AI 系统无法提前预计算。
- 单次最多返回 500 条且没有游标，大量同秒到期任务只能逐批认领排空。
- 平台只有 `10/20/30` 三种状态。基础设施失败后，AI 系统只能保留本地恢复记录和平台状态 `20`，不能回写失败或延期。
- 当前不处理读取最新上下文与实际发送之间最后一秒出现新客户消息的竞态。
- 生产仍保持 `SOP_PLATFORM_PULL_ENABLED=false` 和 `SOP_PLATFORM_SHADOW_MODE=true`，联调完成前不会消费或发送。
