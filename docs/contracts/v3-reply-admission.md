# V3 Reply 运行时质量门合同

- status: current
- owner: reply-runtime / product
- source_of_truth: V3 Reply 实际调用链、项目宪法与本合同

## 适用范围

本合同只描述 `POST /api/ai/reply/workflow-compatible-v3` 最终 Reply 输出在发送前会导致整轮拒绝并触发一次修复的运行时质量门。Prompt 中的销售建议、离线评测标准和 BI 观察项不等于运行时拦截。

## 允许拦截的白名单

### 1. 结构错误

- 缺少 `evidence_join`、`reply_messages` 为空或消息对象/类型/content 非法。
- text 内嵌图片 URL，图片/视频 URL 非法，门店卡或收款卡 payload 非法。
- 同轮多张收款卡、重复人工接管通知、人工接管通知顺序非法。
- 结构化交付只有卡片/媒体而没有客户可见文字。
- 策略决策的运行必需 schema 非法，或已选择话术与策略节点外键不一致。

### 2. 素材与图片

- `selected_content_ids` 不是本轮可选候选。
- 图片/视频不来自本轮素材候选或权威案例事实。
- 已声明采用素材，却没有完整交付该素材要求的非文字消息。

### 3. 收款卡

- 权威支付事实已经确认预约金已付，或 Reply 基于客户原话判断客户声称已付。
- 没有引用更早已向客户交付活动和价格的客服消息或已完成活动介绍。
- 金额不是每位 10 元，或不是 `10/20/30/40` 元之一。
- 人数未知却发送 20 元以上；已知人数与金额不一致；人数超过 4 人仍直接发卡。
- 同一轮发送超过一张收款卡。

是否处于普通付款意图、采用哪种销售承接、是否有地址/效果/卡点铺垫、是否存在健康/投诉标签，不由 Python 关键词或额外业务门禁决定。

### 4. 门店

- 门店 ID 不在本轮权威候选，门店卡与门店事实不一致。
- 位置不足、位置歧义、查询不完整、无匹配或无合法候选时擅自发门店卡。
- 单店、多店、广域完整文字列表的交付模式、数量或内容不符合本轮门店解析结果。
- 未确认位置时在文字中断言某地有店、最近、可服务或可直接接待。

门店已正确交付后是否继续追问到店时间属于模型销售判断，不是质量门。

### 5. 预约完成态

只有明确宣称“已留位/已经留位”“约好了/已预约/预约成功”“已排客/排客成功”及其直接同义完成态，才要求本轮存在权威预约事实。

营业时间、档期可用、可以直接到店、已安排、登记完成等其他措辞不在本运行时拦截内，由模型根据上下文和权威事实自行处理，并继续接受离线质量评测。

## 独立保留的停止联系保护

客户明确要求“别联系、别发了、取消接收”等退订时，Reply 不得同时推进销售、发送素材/门店/收款结构或执行写动作；一次修复不得把已识别的明确退订降级。这是项目长期安全边界，不属于可取消的普通销售质量门。

## 明确不拦截

- 一轮出现多个问题，或 `action=ask` 但文字没有问号。
- 已确认门店后没有继续追问日期/时段。
- 普通软拒绝、忙碌、愤怒、暂停营销标签、活动卡点仍在时模型选择继续回答或推进。
- 营业时间、具体档期、直接到店、普通“已安排”和登记完成措辞。
- 收款卡缺少旧版“地址/效果/卡点承接”或“当前行动信号”审计字段。

新增任何运行时拒绝条件前，必须更新本合同，并同时加入“应拦截”和“不得拦截”的确定性测试；不得把普通业务语义改回 Python 关键词分支。
