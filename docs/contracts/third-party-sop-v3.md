# 第三方 SOP V3 合同

- status: current
- owner: SOP/platform integration
- last_verified: 2026-09-09 Asia/Shanghai
- source_of_truth: 当前 main SOP 代码、第三方 `/event/trigger/consume` 合同与生产日志

## 任务与内容是两个消费对象

- 到期任务来自 `/event/trigger/pending`，主键是 `taskId`，任务终态是 `30` 或 `70`。
- 待发送内容来自 `/event/trigger/sop-messages`，主键是返回项 `id`，消费回写字段是 `messages[].msgId`。
- 两者使用同一个 `/event/trigger/consume` 接口，但语义和字段独立。
- `contentExhausted` 是作废同行程剩余等待时间任务的独立开关；当前执行链不推断、不主动提交。

正常执行链不使用任务状态 `20`。任务可以从 `10` 直接进入 `30` 或 `70`：

- 主动发送接口正常返回，或接口已调用但结果无法确认：任务 `status=30`，并在同一次请求中只回写本次发送的一个 `msgId,status=30`。结果无法确认时必须保留审计，禁止重发。
- 仅客户已开口、客户关系已删除、人工接管三种已承接业务结果：任务 `status=70`，不传 `messages`，不得改变任何待发送内容状态。
- `/sop-messages` 无可消费内容、内容组/`msgId` 无效，或企微聚合平台明确拒绝发送：任务 `status=70`，不传 `messages`；本地审计、策略回传和告警必须明确记录为失败，不能展示为正常“无需发送”。
- 客户状态查询、第三方接口调用及其他尚未形成明确终态的失败：任务保持未消费并进入恢复，不传 `messages`。
- 当前 AICS 不向 `messages` 写 `40` 或 `70`。

## 确定性执行门槛

每条到期任务只做三个发送资格判断：

1. 权威会话中客户从未开口。
2. 客户关系未删除。
3. `ai_auto_reply=true`，当前由 AI 托管。

只有三项同时成立，才允许调用 `/event/trigger/sop-messages`。客户已开口、客户关系已删除或人工接管时，任务回传 `70` 并回传业务策略数据。字段缺失、响应不合法或查询失败属于执行失败：不得查询/发送内容，任务保持未消费并恢复、预警。

当前第三方 SOP 路径不调用模型，不加载客户/订单业务上下文，不生成过渡语，不改写内容，也不做夜间、过期、卡点或销售阶段判断。

## 内容选择与发送

```text
/event/trigger/pending
→ 查询 conversation/status 与 conversation
→ 三项门槛通过
→ /event/trigger/sop-messages(eventLogId)
→ 选择 nextGroup（或列表第一条未发送组）
→ 原样发送该组 message_content 的全部合法消息
→ /event/trigger/consume(taskId=30, messages=[当前 msgId=30])
→ /event/trigger/service-rule-data
```

- 一轮只发送一组，只消费该组的 `msgId`。
- 即使接口返回还有其他组，也不设置 `contentExhausted`，不消费其他 `msgId`。
- 不联动消费历史兼容任务；每个 `/pending` 任务必须独立判断、独立发送、独立回传。
- 主动发送使用基于 `msgId` 的稳定幂等键；不同到期任务再次取得同一内容组时不得重复产生客户消息。
- 主动发送接口正常返回即视为本次发送完成，包括返回“平台已受理/提交结果待回调”；不等待消息送达回调再消费。
- 主动发送接口明确返回拒绝（如账号未绑定、AI 映射缺失）时，任务以失败口径消费 `70`，不消费 `msgId`。
- 已持久化上述明确拒绝结果的恢复任务只能补做任务 `70`、策略回传和告警，禁止再次调用主动发送接口。
- 主动发送调用抛出超时、断连或其他无法证明已被明确拒绝的异常时，以“接口已调用”为幂等边界：任务和本次唯一 `msgId` 联合消费 `30`，记录“发送结果未确认”，不得查询后重发。
- 若第三方消费接口拒绝该联合消费并明确返回“`msgId` 已绑定其他任务”，不得省略 `messages` 让平台自动绑定下一组；改为任务 `70`、不消费任何 `msgId`，按第三方内容绑定异常回传并预警。
- 管理页人工补发当前关闭；终态任务不能通过补发从 `70/30` 改为另一终态，也不能绕过显式 `msgId` 联合消费约束。

## 不发送与失败

以下三种情况是平台能够承接的业务终态，消费任务 `70`、不消费内容、回传对应策略数据且不预警：

- 客户已经开口。
- 客户关系已删除。
- 人工接管或 `ai_auto_reply=false`。

以下情况是失败终态：消费任务 `70`、不消费任何 `msgId`，回传失败策略数据并预警；任务终态完成后允许后续顺序继续：

- `/sop-messages` 没有下一组。
- `msgId` 缺失或消息内容组不合法。
- 企微聚合平台明确拒绝发送，例如 `account_unassigned`（企微账号未绑定客服用户或超级客服 AI 映射）。

以下情况尚不能形成终态：不消费任务、不消费内容，保留最早未完成任务并阻断后续顺序，进入恢复并预警：

- 客户状态、会话或内容接口异常/字段不完整。
- 身份字段或 `eventLogId` 缺失。
- 其他发生在主动发送接口调用之前、且无法归入失败终态的处理失败。

主动发送接口已经调用但抛出超时、断连或结果未知异常，不归入上述失败：按业务幂等约定联合消费任务 `30 + 当前 msgId=30`，不重发，并在审计中标记 `submission_unconfirmed`。这表示“已完成调用且停止重试”，不等于企微真实送达已经得到确认。

每个任务生命周期最多产生一条失败预警。预警必须给出失败类型和责任方向：第三方任务/内容接口、我方客户状态接口、企微聚合平台消息发送、我方主动发送调用、我方运行服务或待确认。企微聚合平台已明确返回失败响应时，责任方向必须归为“企微聚合平台消息发送”，并保留安全的上游错误码；例如 `account_unassigned` 应展示“消息发送未成功，原因：企微账号未绑定客服用户或超级客服 AI 映射”。只有连接超时、调用链异常等无法确认上游响应的故障才归我方主动发送调用或待确认。告警失败不改变任务或内容消费结果，并由独立队列退避重试。

## 恢复与回调

- 发送接口调用事实、选中的 `msgId` 和原始消息必须在任务/内容联合消费前持久化。
- 已记录 `send_invoked_at` 的任务，无论从恢复队列还是普通 `/pending` 再次进入，都只能完成原 `taskId + msgId` 消费，禁止再次调用主动发送。
- 发送已经发生而 `/consume` 发生超时或暂时性失败时，只重试同一个 `taskId=30 + msgId=30` 请求，禁止重发客户消息；明确的 `msgId` 绑定冲突按前述失败终态关闭，不持续占用任务。
- 任务消费成功而策略数据失败时，只重试 `service-rule-data`。
- 消息送达回调仅补充审计，不再反向改变本执行链已经提交的任务或内容状态。
- 正常执行和恢复执行必须使用同一客户任务锁；本实例仍在排队或执行中的任务不得被恢复线程并发处理。
- 恢复进入锁后必须重新读取事件终态和本地发送证据。已有 `sent_at`、平台已接受状态及消息 ID 等明确发送证据时，不得再次调用主动发送，也不得把任务降级为 `processing_retry`、`send_failed` 或无需发送；只允许继续恢复尚未完成的同一 `taskId + msgId` 消费和策略回传。
- 确定性第三方 SOP 的恢复不得进入旧模型决策路径。旧执行模式只隔离审计，不发送、不消费。
- 正常队列与确定性恢复必须复用同一个客户锁和同一套确定性状态机；恢复入口不得调用旧单任务模型路径。
- 第三方 `/pending` 没有返回任务时属于正常空轮询：我方不生成任务、不消费、不回传、不告警。它与“已返回任务但 `/sop-messages` 缺少内容”不是同一种情况。

## 两类独立回传

1. `/event/trigger/consume`：同时承载任务终态和可选的本次内容结果。
2. `/event/trigger/service-rule-data`：记录本任务的处理场景和结果。

两者必须分别记录请求、响应、异常与时间，凭证、鉴权头和客户消息正文不得进入告警。
消息送达回调只提供真实送达事实，不能替代以上两个接口。

## 策略场景字段

`service-rule-data` 必须发送 `sceneCode`、`sceneName`、`remark`，不得把平台原始 scene 或模型文本直接当枚举值。当前枚举：

| sceneCode | sceneName | remark | 终态 |
|---|---|---|---|
| `sop_sent` | SOP发送成功 | SOP消息已发送 | 30 |
| `sop_send_failed` | SOP发送失败 | 第三方内容缺失/无效；任务 70，不消费内容并预警 |
| `wecom_aggregate_send_failed` | 发送失败｜企微聚合平台 | 聚合平台明确拒绝；任务 70，不消费内容并预警 |
| `humantakeover` | 人工接管 | 当前会话由人工接待 | 70，不消费内容，不预警 |
| `customer_deleted` | 客户删除 | 客户关系已删除 | 70，不消费内容，不预警 |
| `sop_no_send_all_filtered` | 客户已开口 | 客户已经回复，不发送固定SOP | 70，不消费内容，不预警 |

## 历史恢复隔离与告警可用性

- 只有本合同产生并持久化了 `deterministic_customer_gate`、`deterministic_task_no_send` 或 `deterministic_task_failure` 标记的任务允许自动恢复。
- 旧执行模式的纯历史记录继续保留为 `platform_legacy_quarantined`，不自动重放。若第三方当前 `/pending` 仍返回该任务，则按我方旧链路失败消费任务 `70`，不调用主动发送、不消费任何 `msgId`；只有当前 pending 中的任务会被收口，不能批量翻出已经离开第三方队列的历史记录。
- 钉钉失败告警重试使用独立后台循环。告警机器人停用、网络失败或业务错误不得阻塞 SOP 轮询、门槛判断、发送、消费或恢复；告警事件继续持久化并退避重试。
- 明确发送成功证据优先于被旧恢复流程污染的本地状态；客户已开口、客户关系已删除和人工接管的本地审计事实也必须抑制包装后的误告警。
- 管理页展示同样以明确发送成功证据为准；旧恢复在发送之后写入的模型错误只保留在原始审计中，不得继续把任务展示为发送失败或处理异常。
- 告警即时发送和重试必须先原子抢占投递租约；新鲜租约不可并发投递，进程崩溃后的过期租约可以恢复。

## 未开口规则

当权威会话事实确认客户未开口时，SOP 内容直接发送，不调用模型决定是否发送。会话拉取失败或客户消息时间不可靠时不得把客户当作未开口。

任务计划时间只用于排序和审计，不构成首次发送的失效窗口。即使任务已逾期，也必须重新执行未开口、未删除、AI 托管三个实时门槛；不能仅因超过固定分钟数消费为 `70`。发送接口结果不确定时不再等待或重发，按已调用终态联合消费任务与当前 `msgId`。

所有任务统一执行“未开口、未删除、AI 托管”三项门槛，不再按任务类型进入模型判断。企微自动开场白不算真实客户回复；其余真实客户消息均视为已经开口。会话响应缺少客户关系或消息列表、请求失败时，任务保持未消费且不查询或消费消息内容。

客户真实回复需要回写策略数据时，只能在同一 `corp_id + wechat + external_userid` 边界内，关联回复时间之前最近一条真实 `status=sent` 平台 SOP 任务。`platform_customer_id` 必须来自任务显式字段或客户资料查询，不得使用 `external_userid` 补位。Shadow、未发送、失败和 `completed_without_send` 均不得关联；无匹配任务属于正常 `skipped`，不记录告警。平台任务 ID 从平台事件或 `platform-sop:<task_id>` 幂等键解析，重复回复回写仍须幂等。

## 日志审计

管理页日志版本为 `sop_platform_run_view_v3`，历史 V2 只做展示兼容。任务审计必须区分确定性门槛、提交发送、消息内容消费、任务消费、送达回调和策略数据回传；不得记录 token、鉴权头或密钥。

## 运行监控口径

- `/admin/sop-platform-dashboard` 是只读 MySQL 聚合接口；默认管理页不因查看看板而访问第三方 pending 接口。
- `/analytics/sop` 是管理 BI；`/logs/sop-platform` 是批次与任务证据；`/logs/sop` 是当前第三方任务和历史接收链共用的底层事件审计。三者不得混为同一业务口径。
- 平台任务、本地任务、客户和真实发送消息必须分别计数，不能把批次数、人数和消息条数相加或互相替代。
- “发送完成”包括主动发送接口正常返回，以及接口已调用但结果未知后按业务约定停止重试的任务；两者都必须使用同一请求回传唯一 `msgId=30`，管理页应区分 `delivered` 与 `submission_unconfirmed`，不能把后者解释为真实送达确认。
- “无需发送”与“异常/未完成”分开统计；原因缺失显示为未记录，不猜测业务状态。
- 队列、执行中和平台待处理数从 worker 进程 `/health` 获取；控制进程没有后台 worker，不能用其状态判断任务服务关闭。
