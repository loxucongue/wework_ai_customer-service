## 消费状态

- `20`：任务已占用，等待发送结果；不是终态。
- `30`：消息真实发送完成；消费终态。
- `70`：第三方平台历史“无需发送”终态；AICS 不再主动写入该状态。
- `contentExhausted`：内容序列是否耗尽，与单任务是否终态分开。

只有存在真实发送证据的任务才能回传 `30`。等待送达回调时不能提前回传；发送失败不能伪造 `30`。接口失败必须保存请求、响应、错误和时间，并由恢复任务重试。

发送阶段的企微聚合平台 `409`、重试到期或其他确定失败只记录为 `send_failed/platform_failed`，不得回传 `30` 或 `70`，也不得消费 `/event/trigger/sop-messages` 返回的内容 `msgId`。网络超时或没有平台消息 ID 的“已受理”属于结果未知；必须等待回调或从会话中查到相同发送证据后，才能回传 `30`。失败或未知任务会锁住同一销售接触档案的后续 SOP；修复后先恢复前序任务，不能跳发后序内容。

同一销售接触档案的到期内容严格按计划时间和顺序号串行处理。每轮只允许判断并发送最早一组；模型跳过最早组、选中后续组、最早组发送失败，或命中退订、客户删除、人工接管、夜间等不发送条件时，均记录 `send_failed/platform_sequence_blocked`，不回传 `30` 或 `70`，后续组保持等待。只有前序组确认发送成功，才释放下一组。

## 两段式任务来源

第三方 SOP 是一条业务链，不是两个独立产品队列：

```text
/event/trigger/pending              到期触发节点（新任务可能没有消息内容）
/event/trigger/sop-messages         按 eventLogId 查询对应的实际发送内容
→ 按客户、接待 WeChat 和平台运行标识配对
→ 判断/发送 → consume → service-rule-data → 送达确认
```

- 触发节点决定任务何时到期；不得因为其内容为空而丢弃或直接消费。
- 内容节点提供可发送消息；配对成功后必须保留触发节点与内容节点的关联审计。
- 任一来源读取失败时，本轮不发送、不消费；保留失败事实，等待下次轮询恢复。
- 夜间命中禁止发送时，所有关联任务保留为失败阻塞并且不消费；不得跳过这些内容继续发送后序任务。
- 到期触发节点若由配对内容完成真实发送，触发节点与内容节点均回传 `30`；这表示同一发送结果，不是重复发送。

## 失败预警

- 未取得真实发送成功证据的任务统一视为失败并预警，包括业务不发、阻塞、接口异常、重试中、发送未确认和 Shadow。
- 已有真实发送证据但 `consume(30)` 或策略数据回传失败，不属于消息未发生；继续恢复下游回传，禁止再次发送客户消息。
- 告警使用独立持久化事件去重和退避重试；告警失败不得消费 SOP、释放后序或影响发送恢复。
- Webhook 与加签 secret 只允许保存在服务器环境变量中，不得进入 Git、业务审计或日志。

## 两类独立回传

1. 消费接口 `/event/trigger/consume`：记录占用和终态消费状态。
2. 策略数据接口 `/event/trigger/service-rule-data`：记录本次处理场景。

消息送达回调只提供真实送达事实，不能替代以上两个接口。

## 策略场景字段

`service-rule-data` 必须发送 `sceneCode`、`sceneName`、`remark`，不得把平台原始 scene 或模型文本直接当枚举值。当前枚举：

| sceneCode | sceneName | remark | 终态 |
|---|---|---|---|
| `sop_sent` | SOP发送成功 | SOP消息已发送 | 30 |
| `sop_send_failed` | SOP发送失败 | SOP消息发送失败 | 失败事实 |
| `humantakeover` | 人工接管 | 当前会话由人工接待 | 失败阻塞，不消费 |
| `customer_deleted` | 客户删除 | 客户关系已删除 | 失败阻塞，不消费 |
| `sop_no_send_all_filtered` | 暂无合适内容 | 当前没有适合发送的SOP内容 | 失败阻塞，不消费 |
| `sop_no_send_skipped_prefix` | 前序内容不可发送 | 前序SOP内容未发送，禁止后序越过 | 失败阻塞，不消费 |
| `sop_no_send_compat_resolved` | 兼容任务已处理 | 配对内容已真实发送 | 30 |
| `sop_no_send_duplicate` | 内容重复 | 已有相同真实发送证据 | 30 |
| `sop_no_send_invalid_content` | 平台内容无效 | 平台任务没有合法消息内容 | 失败阻塞，不消费 |
| `sop_no_send_quiet_hours` | 夜间禁止 | 夜间SOP不发送 | 失败阻塞，不消费 |

## 未开口规则

当权威会话事实确认客户未开口时，SOP 内容直接发送，不调用模型决定是否发送。会话拉取失败或客户消息时间不可靠时不得把客户当作未开口。

客户真实回复需要回写策略数据时，只能在同一 `corp_id + wechat + external_userid` 边界内，关联回复时间之前最近一条真实 `status=sent` 平台 SOP 任务。`platform_customer_id` 必须来自任务显式字段或客户资料查询，不得使用 `external_userid` 补位。Shadow、未发送、失败和 `completed_without_send` 均不得关联；无匹配任务属于正常 `skipped`，不记录告警。平台任务 ID 从平台事件或 `platform-sop:<task_id>` 幂等键解析，重复回复回写仍须幂等。

## 日志审计

管理页日志版本为 `sop_platform_run_view_v3`，历史 V2 只做展示兼容。任务审计必须区分模型决策、提交发送、真实送达、消费回传和策略数据回传，并保留完整业务 JSON；不得记录 token、鉴权头或密钥。

## 运行监控口径

- `/admin/sop-platform-dashboard` 是只读 MySQL 聚合接口；默认管理页不因查看看板而访问第三方 pending 接口。
- `/analytics/sop` 是管理 BI；`/logs/sop-platform` 是批次与任务证据；`/logs/sop` 是当前第三方任务和历史接收链共用的底层事件审计。三者不得混为同一业务口径。
- 平台任务、本地任务、客户和真实发送消息必须分别计数，不能把批次数、人数和消息条数相加或互相替代。
- “发送完成”只按主动发送接口已接受且保存了平台消息 ID 的任务计数；会话归档可能包含人工消息，不能据此反推 SOP 已发送。
- “无需发送”与“异常/未完成”分开统计；原因缺失显示为未记录，不猜测业务状态。
- 队列、执行中和平台待处理数从 worker 进程 `/health` 获取；控制进程没有后台 worker，不能用其状态判断任务服务关闭。
