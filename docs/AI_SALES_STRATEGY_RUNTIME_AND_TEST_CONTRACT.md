## V3 链路

```text
客户消息 + 近聊 + 权威事实
  → V3 语义路由与证据收集
  → Reply 同时输出客户回复和结构化 policy_decision
  → 代码只校验稳定 key、事实、安全和发送边界
  → 即时回复
  → 可选 shadow 延时任务与审计
```

`policy_decision` 包含主任务、次任务、实时意图、情绪、成交序列状态和卡点判断。模型负责业务语义；代码不得用关键词规则替代模型判断普通意图和卡点。

素材目录启用后，系统根据模型产生的语义摘要召回候选，再按动态事实、硬风险、近期重复和 URL 权威性过滤。Reply 最多采用一个解题方向，必须自然改写；图片和视频只能使用本轮候选明确提供的 URL。

## 交易与发送硬边界

- `closing_decision` 只管理序列状态，不授权开单、发卡或确认预约。
- 预约金卡仍要求同门店、同金额的真实有效未付订单。
- 人工接管、明确退订、已付终态、会话读取失败、客户已回复和重复发送都会阻止延时任务。
- 延时任务按 `corp_id + wechat + external_userid/customer_id` 隔离。
- 客户回复后取消旧序列，重新进入当前 V3；不得机械发送下一节点。
- shadow 任务永远不调用真实发送客户端。
