# 第三方 SOP 单任务执行与失败预警

- status: current
- owner: SOP/platform integration
- last_verified: 2026-09-08 Asia/Shanghai
- implementation: `ai_paths/app/services/sop_platform_task_service.py`
- contract: `docs/contracts/third-party-sop-v3.md`

本文按“一条第三方 SOP 任务”说明当前生产代码的实际执行路径，供后续将执行职责迁移到第三方 SOP 平台时逐项对齐。本文描述的是当前实现，不代表已经完成平台迁移。

## 一、成功、失败预警与非预警阻断口径

- 成功：已取得主动发送接口返回的平台消息 ID，或送达回调/会话核对提供了同一条消息的明确发送成功证据。
- 失败预警：除明确排除项外，消息未发送且存在可处理异常，包括内容/身份/会话错误、顺序异常、过期、夜间、模型不发、占用失败、明确发送失败、恢复失败和 Shadow。
- 非预警阻断：客户关系已删除、人工接管、发送结果尚未确认。这三类不算发送失败，不发送钉钉预警。
- 未发送任务无论是否预警，都不回传 `30`/`70`，不消费消息内容，不释放同一客户后续任务；发送结果未确认继续等待证据或恢复。
- 主动消息已经成功、但后续 `consume(30)` 或策略数据回传失败，不属于“消息未发生”；它保留恢复状态和日志，但不发送“未发生”告警，也不得再次给客户发消息。

## 二、单任务标识和顺序边界

一条任务至少需要下列字段才能执行：

| 字段 | 用途 | 缺失结果 |
|---|---|---|
| `taskId` | 平台任务、幂等、消费回传和告警主键 | 失败，不发送 |
| `eventLogId` | 从到期触发任务查询实际 SOP 内容 | 失败，不发送 |
| `corpId` | 企业边界 | 失败，不发送 |
| `customerId` | 平台客户边界 | 失败，不发送 |
| `externalUserid` | 外部联系人边界 | 失败，不发送 |
| `userId` / `wechat` | 接待员工与企微边界 | 失败，不发送 |
| 计划时间、顺序号 | 同一销售接触档案内排序 | 无法可靠排序时失败关闭 |

销售接触档案固定为 `corp_id + wechat + external_userid/customer_id`。同一档案严格串行：最早未确认任务未成功前，后续任务只能等待，不能越过。

## 三、任务进入后的接口和判断顺序

| 顺序 | 调用/动作 | 使用字段 | 判断与结果 |
|---:|---|---|---|
| 1 | `POST /event/trigger/pending` | `corp_id`、`wechat`、`limit` | 拉取已到期任务。请求失败或返回页不完整：本轮不发送，产生系统失败预警。 |
| 2 | 对每个到期任务调用 `POST /event/trigger/sop-messages` | `eventLogId`、`corp_id`、`wechat`、`limit` | 取得权威消息组。找不到匹配内容：该任务失败预警，不消费。 |
| 3 | 本地持久化任务与原始业务载荷 | `taskId` 和完整任务字段 | 持久化失败：任务失败预警，不进入发送。 |
| 4 | 查询同一销售接触档案内更早的未确认任务 | 身份边界、计划时间、顺序号 | 存在更早任务：当前及后续任务进入顺序等待；最早阻塞任务失败预警。 |
| 5 | 本地前置检查 | 任务年龄、夜间配置、消息格式、身份一致性 | 过期、夜间、内容无效、混合身份或身份缺失：失败预警，不消费，不放行后序。 |
| 6 | 并行调用 `GET /api/v1/platform-agent/ai-outreach/conversation/status` 和 `GET /api/v1/platform-agent/ai-outreach/conversation` | `corp_id`、`customer_id`、`external_userid`、`user_id`、`wechat` | 状态或会话字段不完整、接口异常：失败关闭并预警。客户已删除、人工接管：阻断发送但不预警。 |
| 7 | 读取客户与订单上下文 | `GET /platform_agent/customer/get_customer_info`、`GET /platform_agent/order/index` | 用于当前已开口客户的业务上下文。该服务当前允许降级为空上下文；迁移时必须明确是否继续保留此降级。 |
| 8 | 决定是否发送 | 会话时间线、客户状态、任务内容 | 客户权威未开口：最早内容直接发送，不调用模型。客户已开口：当前实现仍调用模型判断最早内容是否可发，详见“迁移缺口”。 |
| 9 | `POST /event/trigger/consume`，状态 `20` | `taskId` | 发送前占用任务，不是终态。失败：不调用发送接口或进入恢复。 |
| 10 | `POST /api/v1/platform-agent/ai-outreach/send` | 完整身份、`plan_id`、发送幂等键、原始消息列表 | 只允许发送最早任务。明确失败：失败预警并保留恢复；仅受理或结果未知：等待证据，不预警。 |
| 11 | 保存发送证据 | 平台消息 ID、送达状态、时间 | 明确成功证据必须先于后续消费与策略回传持久化，防止后续接口失败造成重复发送。 |
| 12 | `POST /event/trigger/consume`，状态 `30` | 已成功任务 `taskId`；两段式兼容任务还包括关联触发任务 ID | 仅发送成功后调用。关联触发任务与内容任务的两个 `30` 表示同一次发送，不是两次消息。 |
| 13 | `POST /event/trigger/service-rule-data` | `taskId`、`sceneCode`、`sceneName`、`sendStatus`、`remark` 等 | 回传本次策略结果。失败时恢复回传，不得重新发送客户消息。 |
| 14 | 释放顺序锁 | 本次已完成任务 ID | 只有前序发送成功且终态回传完成后，下一条任务才能进入发送。 |

## 四、发送返回和回调判断

| 情况 | 本地处理 | 平台消费 | 是否失败预警 |
|---|---|---|---|
| 发送接口同步返回明确消息 ID/成功证据 | 立即保存 `sent` 证据 | 回传 `30`，再回传策略数据 | 否 |
| 发送接口仅返回受理，等待送达回调 | 保持 `sending/platform_delivery_pending` | 不回传 `30` | 否，属于发送结果未确认 |
| 网络超时或提交结果未知 | 保持 `platform_send_uncertain`，先查送达证据再决定是否重试 | 不回传 `30` | 否，属于发送结果未确认 |
| 回调 `send_succeeded` | 保存回调证据并完成后续回传 | 回传 `30` | 否 |
| 回调 `send_failed` / `partial_failed` | 保存失败并进入重试或终态失败 | 不回传 `30`/`70` | 是 |
| 回调状态为空或无法识别 | 保持未确认 | 不回传 `30` | 是 |
| 会话中查到同一 `plan_id/task_id/内容` 的已有发送 | 作为恢复证据，禁止重发 | 补回传 `30` | 否 |

## 五、需要预警的 13 类失败

以下情况属于可处理异常，消息未发送时必须预警：

| 阶段 | 失败情况 | 任务处理 |
|---|---|---|
| 拉取 | pending 接口异常、分页不完整 | 系统级失败预警；本轮不处理 |
| 内容解析 | `eventLogId` 缺失、`sop-messages` 异常、无匹配消息组、消息为空或类型不支持 | 任务失败；不消费 |
| 持久化 | 原始任务、本地幂等任务或发送前审计写入失败 | 任务失败；不发送 |
| 顺序 | 存在更早未确认任务、模型未选最早任务、最早任务不可发 | 前序失败、后序等待；均不得越过 |
| 时效 | 任务超过允许发送窗口 | 失败；不消费 |
| 时间 | 命中夜间禁止发送 | 失败；不消费，白天恢复前序 |
| 身份 | 企业、客户、外部联系人、员工、企微字段缺失或同批身份混杂 | 失败；不发送 |
| 会话 | 会话/状态接口失败、结构不合法、缺少 `ai_auto_reply` | 失败关闭；不发送 |
| 决策 | 已开口客户的模型异常、输出不合法、判定 `no_send`、无法选择最早任务 | 失败；不消费、不放行后序 |
| 占用 | `consume(20)` 失败或状态不符合 | 失败；不发送 |
| 发送 | 主动发送接口明确拒绝、可确认的接口异常、重试中、重试到期 | 失败；保留请求和错误，不消费。仅受理或结果未知除外 |
| 恢复 | 本地原始载荷缺失、恢复异常、第三方已标为未发送 | 失败；保留审计并继续阻塞后序 |
| Shadow | `shadow_send`、`shadow_no_send` | 没有真实发送，均按失败预警 |

明确已有发送成功证据的内容重复，不属于“未发生”；它必须引用原发送证据，禁止再次发送，然后补齐消费与策略数据。

以下三类只保留阻断和审计，不进入失败预警：

1. 客户关系已删除：不再尝试发送，不消费当前内容，不放行后序。
2. 人工接管：AI 停止发送，不消费当前内容；待权威状态恢复后再判断。
3. 发送结果未确认：包括 `accepted`、`platform_delivery_pending`、`platform_send_uncertain`、`delivery_not_confirmed` 和提交超时结果未知；继续等待回调或会话证据。

## 六、当前仍存在的 AI 路径（平台迁移缺口）

“SOP 内容不做 AI 处理、只按接口字段判断”与当前代码不完全一致：

1. 客户权威未开口时，确实直接发送最早的原始 SOP 内容，不调用模型。
2. 客户已经回复时，当前会把会话时间线、客户/订单摘要和最早任务交给模型，模型返回 `send/no_send`、选中任务和可选过渡语。
3. 过渡语还会经过一次模型事实审计；审计失败只删除过渡语，原始 SOP 内容仍可继续发送。
4. 历史单任务兼容路径中的 `useAiCopy=true` 仍允许模型生成或调整内容。

因此，在第三方平台完全接管前必须二选一并形成新合同：保留等价模型能力，或由业务提供覆盖“客户已开口后是否发送、如何衔接、`useAiCopy`”的确定性字段与规则。未完成这一步前，不能宣称迁移后行为等价。

## 七、钉钉失败预警

- 预警对象：13 类可处理失败；拉取链整体异常使用系统级预警。客户删除、人工接管和发送结果未确认明确排除。
- 预警内容：任务 ID、状态、失败阶段、失败原因、客户 ID、接待企微、计划时间、发生时间、发布版本和告警 ID；不包含消息正文、完整外部联系人标识、鉴权头、Webhook 或密钥。
- 去重：同一任务、同一失败类别、同一原因只创建一个持久化告警事件。发送结果后续变成明确失败时，按最终失败原因预警。
- 重试：钉钉发送失败后持久化退避重试；告警失败不改变 SOP 任务状态，也不消费任务。
- 交付语义：告警采用至少一次投递。若钉钉已接收但进程在保存 `alert_sent` 前退出，可能重发；群内可按告警 ID 识别同一事件。
- 配置：仅使用服务器环境变量 `SOP_FAILURE_ALERT_ENABLED`、`SOP_FAILURE_ALERT_WEBHOOK_URL`、`SOP_FAILURE_ALERT_SIGNING_SECRET`、`SOP_FAILURE_ALERT_TIMEOUT_SECONDS`、`SOP_FAILURE_ALERT_RETRY_BATCH_SIZE`。凭证不得进入 Git、文档或日志。

## 八、迁移验收清单

第三方平台接管单任务执行时，至少逐项证明：

1. 任务与内容按 `eventLogId` 正确配对，且不会因触发任务无正文而丢失。
2. 同一销售接触档案严格串行，失败任务不会被消费，后续不会越过。
3. `20`、发送、真实送达证据、`30`、策略数据五个阶段可独立审计和恢复。
4. 13 类可处理失败进入预警；客户删除、人工接管和发送未确认不预警；已有发送证据的下游回传失败不会触发重复客户消息。
5. 客户删除、人工接管、夜间、身份和会话状态未知均阻断发送；其中客户删除和人工接管不预警，夜间、身份和会话异常预警。
6. 已开口客户和 `useAiCopy` 的 AI 迁移方案已明确，不以未评审的字段分支替代当前语义判断。
