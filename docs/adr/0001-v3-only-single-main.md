# ADR-0001：V3-only 与单一 main

- status: accepted
- date: 2026-08-31
- code_consolidated: 2026-09-01

## 决策

客户回复产品只保留 V3；`main` 是唯一长期开发与生产分支。后端 reply、control、worker 可以拆进程，但同一轮发布必须从同一个干净的 main SHA 构建。前端同样只能来自干净 `main`，并与当前接口合同兼容；只有前后端存在耦合改动时要求同批发布，不要求独立前端 release 与后端使用相同构建 SHA。旧产品 V1/V2 路由从应用代码和前端代理删除，公网退役地址由 Nginx 永久返回 410。

## 原因

作出本决策时，生产由两个深度分叉的代码线拼接，旧 worktree 和功能分支容易把已修复规则覆盖回去。只关服务而不整合代码，会停止 SOP 等共享能力；整分支覆盖则会丢失另一条代码线的修复。代码线现已收口，但该风险仍决定后续治理方式。

## 后果

- 收口采用选择性、按模块所有权的合并，不整分支覆盖。
- 后端进程可继续按 reply/control/worker 拆分，但同一轮发布不得从不同分支或不同提交构建；前端按接口兼容性独立发布时也必须来自干净 `main`。
- 历史 schema/第三方协议版本保留兼容，不按字符串清除。
- 发布必须记录 commit、role、interface version 和回滚 release。
